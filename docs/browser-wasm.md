# 浏览器 WASM 实验功能

RetroOne 可以让符合条件的较大 ROM 在浏览器中模拟。详情页统一提供“浏览器运行（实验）”入口；下载时自动使用 NAS 的 HTTP 来源及可用的浏览器 P2P 来源，游戏计算和画面渲染由当前设备承担。

默认行为保持不变：**只有符合原有条件、文件及解压后大小均不超过 20 MiB 的游戏，才自动使用浏览器模式**。本页介绍的实验选项必须手动选择，不会改写游戏的默认启动配置，也不会把游戏库中的大镜像自动下载到手机。

这项功能复用已有的 EmulatorJS WASM 核心。不同平台、游戏和客户端的兼容性差别很大；选项可用表示已通过文件、内核等启动条件检查，不表示这款游戏已经通过实际游玩或 60 FPS 验证。

## 选择启动方式

打开一款游戏的详情页，在开始按钮下选择 **启动方式**：

| 选项 | 下载与运行方式 | 适合的情况 |
| --- | --- | --- |
| 自动选择（推荐） | 保持原来的 20 MiB 自动规则 | 日常使用，无需考虑内核或文件大小 |
| 云游戏 | ROM 留在服务器，浏览器接收画面和声音 | 手机、性能不足的设备、需要家人或智能体观战 |
| 浏览器运行（实验） | 下载完整 ROM 后在浏览器模拟；NAS 提供 HTTP 下载，可用时由其他家庭设备分享分片 | 想用当前设备运行，且设备性能、内存和游戏格式满足条件 |

下拉框中不可用的选项会标为“不可用”；展开 **查看不可用选项的原因** 可以查看缺少的条件。当前设备不满足模拟器的线程或图形要求时，也会限制对应选项；仅缺少 P2P 网络能力不会禁用可通过 HTTP 加载的游戏。键盘可使用标准下拉框操作；手柄聚焦后按确认键，会循环选择可用方式。

选择浏览器运行后，界面会说明需要下载的 ROM 体积。高级设置中的 **允许 P2P 分享** 默认开启：除了接收分片，也会向其他家庭设备发送当前游戏的分片。关闭后只从 NAS 下载；该偏好保存在当前浏览器，不改变其他设备的设置。

下载完成后，仍需等待模拟器加载。**当前实现不是边下边玩，也不是云端画面串流。** P2P 改变的是文件来源，不会减少 ROM 的实际体积或模拟器的内存需求。几 MiB 到几十 MiB 的小 ROM 通常直接通过 HTTP 就能很快加载；P2P 更适合多个设备同时下载同一个较大文件、NAS 上行带宽受限的情况。原来的自动模式继续加载符合条件的小 ROM；如果这台设备已有同款游戏的有效缓存，也会优先读取该文件。

## 当前支持范围

较大 ROM 的实验范围包括 GBA、Nintendo 64、Nintendo DS、Nintendo 3DS、PlayStation 和 PSP。现有小型卡带平台也可以尝试显式选择浏览器运行，但仍须通过各自的格式和体积检查。

| 平台 | 实验入口接受的主要格式 | 额外条件 |
| --- | --- | --- |
| GBA | `.gba`，或只包含一个卡带文件的可验证 ZIP | 已安装对应浏览器核心 |
| Nintendo 64 | `.z64`、`.n64`、`.v64`，或合格的单卡带 ZIP | 已安装对应浏览器核心；性能因游戏而异 |
| Nintendo DS | `.nds`，或合格的单卡带 ZIP | 已安装核心及 `bios7.bin`、`bios9.bin`、`firmware.bin`；双屏和触控需求仍取决于游戏 |
| Nintendo 3DS | 独立 `.3ds`、`.cci`、`.cxi`，或合格的单卡带 ZIP | Azahar 线程核心、HTTPS、跨源隔离、共享内存及 WebGL 2；不接受需安装的 CIA，仍默认走云游戏 |
| PlayStation | 独立 `.pbp` | 已安装核心并提供所需 BIOS；本版不开放 CUE/BIN 多文件组合、M3U 或 CHD |
| PSP | 独立 `.iso`、`.cso`、`.pbp` | PPSSPP 线程核心、配套资源、HTTPS、跨源隔离、共享内存及 WebGL 2 |

格式限制按照 RetroOne 当前锁定的 EmulatorJS **4.3.0-pre 预发布版**核心确定，不能套用原生模拟器的格式列表。例如，原生 PPSSPP 可以支持的某种格式，并不代表当前 WASM 构建也能加载。本版不把 7z、多文件光盘、依赖父包的街机集合或完整 PC 游戏目录打包后直接交给浏览器。

Switch、PS2、PS3、GameCube、Wii 和当前未接入浏览器核心的平台继续使用云游戏。上游新增平台不等于 RetroOne 已安装、适配或验证它。

前端、全部浏览器核心及配套资源按同一版本整体准备，不混用 4.2.3 与 4.3 的文件。资源 URL 含运行包指纹，升级后不会继续命中旧版前端缓存；已有 ROM 目录缓存与个人存档不随核心升级重新下载或删除。可复现下载清单位于 `container/browser-runtime-lock.json`。

PSP 和 3DS 是实验性较强的路径。上游明确要求启用线程，并不保证具体游戏的兼容和图形表现。RetroOne 同时检查锁定核心所需的 WebGL 2 和配套资源。3DS 底屏开启鼠标与触摸输入，保留原比例双屏显示。详见 [EmulatorJS Azahar 文档](https://emulatorjs.org/docs/systems/azahar/) 和 [EmulatorJS PSP 文档](https://emulatorjs.org/docs/systems/psp/)；浏览器线程依赖的跨源隔离要求见 [Emscripten pthreads 文档](https://emscripten.org/docs/porting/pthreads.html)。

3DS 核心仍有明显的性能限制。2026-10-26 在 Apple M5 Max / Chrome 155、Metal 硬件加速、1× 内部分辨率与 HLE 音频配置下，《雷顿教授 VS 逆转裁判》仍持续出现音频供应不足。升级到能启动的核心不代表能够流畅游玩；日常游玩建议选云游戏。详细证据与限制见 [性能说明](performance.md#浏览器-3ds-声音断续)。3DS 浏览器与云端存档目前不自动同步，切换前请保留原进度。

## 下载到设备与缓存管理

支持持久存储的浏览器会自动把下载保留在 **浏览器缓存**（OPFS），不必先选择目录。同一网址、同一浏览器的家庭玩家共用 ROM；再次启动、切换玩家或重新打开网页时，会校验已有文件并复用，不重新下载完整 ROM。游戏存档仍按玩家隔离。

点击顶栏 **下载管理**（或自己的头像 → **下载与分享**）可以查看当前保存位置。在桌面 Chrome/Edge 中，可以点 **选择目录**，选择 Downloads 下专门保存 ROM 的子目录。也可以通过 **使用浏览器缓存** 切回默认位置；切换不会迁移或删除旧位置的文件，重新选择原位置会恢复对应列表。

浏览器缓存受站点存储配额限制，清除网站数据会删除它，浏览器也可能在磁盘空间不足时回收。选择系统目录更适合长期保存大文件。RetroOne 只在选定目录下创建自己管理的子目录，不接管已有的其他文件。目录句柄和列表留在这个浏览器的 IndexedDB 中，不上传服务器；更换网址、浏览器或设备后，缓存和授权不会自动共用。删除网站数据不会删除外部目录中的 ROM，但会丢失管理记录。

外部目录需要重新授权时，启动会打开下载管理；授权后继续原来的启动，不会因为权限暂时失效就再下整份 ROM。存储空间不足或实验模式缺少持久存储能力时，明确显示原因，不悄悄改为一次性大文件下载。不支持持久缓存的旧浏览器仍可按原自动规则临时加载小 ROM，并显示“本次临时加载”；这条兼容路径不保证再次启动时免下载。

管理窗口显示文件大小、下载进度、HTTP/P2P 来源、已分享字节与连接数，支持暂停和继续。关闭管理窗口、切换游戏库/收藏/详情或玩另一款小游戏不会中断下载；游戏工具栏或手机 ☰ 菜单也能打开下载管理，点“返回游戏”会保留同一个模拟器实例。刷新、关闭网页或系统挂起页面后无法保证持续传输，重新打开后按已有分片恢复。下载列表会明确区分可下载分享与可在浏览器运行。游戏卡片及详情页有额外的设备缓存图标，区分已下载、正在下载、校验中、暂停和待授权状态。目录未授权时，历史记录不等于文件已经可读。

**下载接口与模拟器运行分开，但游戏详情只为已支持浏览器运行的游戏显示“下载到设备”按钮。** 已下载的其他平台文件仍可在下载管理器中查看和分享，列表会明确提示尚不能在浏览器运行。默认不设置 512 MiB、1 GiB 等人为下载上限。独立下载 API 仍能服务已有的非浏览器平台任务，例如 Switch NSP/XCI 或 PS2 镜像；这不会让 Switch、PS2 自动具备 WASM 运行能力，详情页不再为这些游戏单独显示下载按钮。禁用或待处理的条目、文件夹资源包、多文件入口和依赖不完整的游戏仍会显示原因，不能把一个入口文件误当作完整游戏。

下载由 WebTorrent 分片校验并直接写入磁盘，不把完整 ROM 组装成内存数组。下载完成后会将分片顺序写成普通 ROM 文件，再删除本任务的分片文件。因此完成时会短暂需要约 **两倍 ROM 大小的磁盘空间**，完成后只保留一份；暂停或关闭网页会保留已有分片。浏览器缓存受 OPFS 站点配额限制；选择的外部目录不受此配额限制，但仍受实际磁盘空间和文件系统能力限制。

网站保持打开且允许 P2P 分享时，完整文件可继续给其他浏览器提供分片。返回游戏库不会停止分享；关闭标签页、浏览器休眠或系统暂停页面后，不能保证继续连接。下次打开网站，在目录仍获授权的情况下自动重新校验文件并恢复未暂停的任务；否则显示重新授权按钮。长期打开页面时会刷新私有 Tracker 票据。完整文件被手动改动会先停止使用，校验或修复完成后才能再次分享。

已经校验的 ROM 可以被当前设备上的不同家庭玩家共用。持久存储可用时，普通自动浏览器模式的首次加载也会进入共享下载库；无需先手动下载。外部目录待授权时不会自动退回临时下载。自动浏览器模式和显式“浏览器运行”都优先复用适用的缓存；退出游戏不会关闭主页管理的下载或做种。文件传给 WASM 时使用磁盘 File 对象，**但当前 EmulatorJS 仍可能把 ROM 读入模拟器内存**，并非已经实现模拟器按需读取磁盘。

## 内存和存档

浏览器实验模式默认取消固定大小上限；管理员仍可设置可选限额。游戏格式、核心、BIOS、线程与图形要求保持有效。选择目录解决的是下载和长期保留文件，不能增加 WASM 可寻址内存或客户端实际内存。浏览器缓存与外部目录均不能降低模拟器运行时的内存需求。

当前锁定的 EmulatorJS 会完整加载 ROM，并写入模拟器的内存文件系统；加上模拟器内存、临时缓冲区和图形资源，浏览器的实际内存占用可能达到 ROM 体积的数倍。更换 HTTP 或 WebTorrent 不会改变这一点。实现依据见 [EmulatorJS 加载实现](https://github.com/EmulatorJS/EmulatorJS/blob/main/data/src/emulator.js)。

建议先用较小的自有游戏，在内存充足的电脑上验证输入、声音、保存和恢复，再尝试更大的文件。手机浏览器更容易受到内存限制；页面被系统回收或浏览器崩溃时，请使用云游戏，不要只提高服务器下载限额。

浏览器模拟继续隔离各玩家的存档。PSP 新增同一玩家、同一游戏的 [游戏内云存档同步](cloud-saves.md)：在云端保存并结束游戏后，浏览器启动前读取进度，游戏内保存后自动同步回服务器。其他平台的浏览器存档与云端存档目前仍分开；即时存档 `.state` 不自动转换。HTTP 和 WebTorrent 是同一浏览器模拟器的两种下载路径，不会创建第二个家庭玩家。

需要家人或智能体观看时，请使用云游戏。当前的观战、服务端截图及远程控制链路不捕获本地浏览器的 WASM 游戏画面。WebTorrent 下载连接也不等于游戏联机：它不会同步人物、房间、存档或手柄输入。

## WebTorrent 的工作方式

本版采用 **HTTP Web Seed 保底、浏览器间 WebRTC 互传** 的结构：

```text
NAS 上的 ROM ── HTTP Web Seed ──→ 浏览器 A ──→ WASM 模拟器
                                      ↕ WebRTC 分片
                                  浏览器 B
```

NAS 提供完整文件和分片校验所需的元信息。参与同一游戏下载的浏览器，可以从 HTTP 节点及已拥有相应分片的浏览器接收内容。**没有其他浏览器做种时，仍可从 NAS 的 HTTP 节点下载，这不是 P2P 故障。** 下载页应区分 HTTP 来源和其他浏览器来源的数据，不能把全部下载流量都称为 P2P 加速。

这不要求 NAS 通过 aiortc 扮演 WebRTC 文件发送端，也不把普通 BitTorrent TCP/UDP 客户端当成浏览器节点。浏览器节点之间使用 WebRTC；HTTP Web Seed 是另一条标准下载路径。WebTorrent 支持 Web Seed，并会在下载期间把已有分片提供给其他节点，详见 [WebTorrent API 文档](https://webtorrent.io/docs)。

默认使用自行部署的私有 Tracker，并限制在应用提供的游戏内容范围内，不连接公共 Tracker。浏览器页面的参与是下载和分享分片，不会把整个 NAS 目录公开做种。

Tracker 复用 WebTorrent 项目的 [bittorrent-tracker](https://github.com/webtorrent/bittorrent-tracker)。所有玩家共用网关的 `/rom-tracker` WebSocket 路由，通过现有 HTTPS 端口访问；不需要再对外开放 Tracker 的内部端口。每次启动获得仅适用于当前内容的限时票据。共享数据目录中的 `.webtorrent-secret` 是部署私钥，不应上传、公开或复制到客户端。

## 已完成的验收

完整 4.3.0-pre 运行包已用 NES、GBA、PSP 的真实 WASM 核心验证启动与帧更新；NES 8 KiB、GBA 32 KiB 合成游戏内存档从 4.2.3 同源升级后逐字节一致。以用户自有《雷顿教授 VS 逆转裁判》CCI 验证双屏、手柄输入、底屏触控、新建存档及进入序章首场景；Mac Chrome 中仍出现 WebGL 警告和部分横纹，未完成全游戏验收或 60 FPS 测量。已下载的原 ROM 可复用，不因核心升级改变分片身份。

2026-10-26 的目录缓存验收使用 8 MiB 合成文件、两个独立 Chrome 环境：A 通过 HTTP 下载到真实文件系统句柄，B 禁止 HTTP ROM 请求后仍通过 A 获得全部 8 MiB；重新打开 A 后恢复 IndexedDB 目录记录、重新校验且没有再次下载 ROM。另验证了同源多标签页互斥、文件被修改后的检测和修复、无 WebRTC 时的 HTTP 校验下载。原生操作系统目录选择器没有被自动点击；自动验收使用真实 OPFS 目录句柄代替用户选择的磁盘目录，Downloads 授权对话框仍需实际设备点选验证。 另使用真实 API 和 mgba WASM 验证了自制 1 MiB GBA 程序的缓存自动启动、32 MiB 程序的显式浏览器启动；两者都直接复用已校验的磁盘 File，出现可见游戏画面且没有重新下载 ROM。退出游戏 iframe 后主页分享任务保留，存档标识没有变化。

2026-10-25 使用自制的 32 MiB GBA 测试程序验证了 HTTP 下载和 WASM 运行。另在 NAS 的独立 Docker 测试实例和 Linux Chrome 147 的两个独立浏览器上下文中验证：A 从 NAS 完成下载并启动模拟器；B 被禁止访问 HTTP ROM 地址后，仍全部通过 A 获得 32 MiB，并启动模拟器。停止 B 的分享后，模拟器继续运行。

这证明了下载、分片校验、浏览器互传与 WASM 的完整路径，不代表全部商业游戏、手机或跨公网网络均已通过测试。Mac 测试环境中仅有 mDNS 候选的连接未成功，HTTP Web Seed 正常；网络限制时应保留 HTTP 下载，或由管理员配置下面的 STUN/TURN 服务。

本版不提供公共 Tracker 配置。可选的 STUN/TURN 是浏览器建立网络连接所需的服务，与查找游戏下载节点的 Tracker 不是同一个功能。

浏览器间连接还受 NAT、防火墙、网络隔离和 WebRTC 策略影响。Docker Bridge 中的 HTTP 节点能够访问，不代表两个浏览器之间一定能互连。部署时应分别验证 HTTP 下载和浏览器互传；不能仅凭网页打开或 Tracker 建连成功就声称 P2P 可用。

未选择持久目录的临时浏览器启动路径中，浏览器或服务未提供 P2P 能力时，入口直接使用 HTTP。WebTorrent 组件、连接失败或下载停滞时，会自动改用 HTTP 重试一次；这可能重新下载完整文件，但仍运行同一款浏览器游戏，并保留相同的玩家存档身份。HTTP 也失败时显示重试按钮，不无限重试。取消下载、文件校验失败、内存不足及模拟器加载失败不会触发这种自动重试，更不会切换成云游戏或启动另一个游戏会话。

## 管理员配置与验证

`RETROONE_WASM_MAX_BYTES` 控制可选的浏览器实验模式体积上限，单位为字节，默认 `0` 表示不设人为上限；例如设为 `536870912` 可限制到 512 MiB。已取消原来的 1 GiB 硬上限。该变量不限制独立“下载到设备”，不改变自动模式的 20 MiB 阈值，也不会增加客户端可用内存。部署时须将变量传入每个玩家容器，并检查后续新增玩家实例是否继承一致的设置。

`RETROONE_WEBRTC_ICE_SERVERS` 是可选的 JSON 数组，默认 `[]`：**不预设公共 STUN/TURN，也不连接公共 Tracker**。默认状态下浏览器只尝试当前网络可用的直接连接；跨路由、VPN 或公网 NAT 环境可能无法互连，HTTP Web Seed 仍是下载保底来源。私有 Tracker 能交换信令，不代表已经打通浏览器间的数据通道。

管理员可以配置自己运营或明确选用的 STUN/TURN 服务。例如，在部署使用的 `.env` 中设置以下示例，并将主机名、用户名和凭据替换为实际服务配置：

```dotenv
RETROONE_WEBRTC_ICE_SERVERS='[{"urls":"stun:stun.example.test:3478"},{"urls":["turn:turn.example.test:3478?transport=udp","turns:turn.example.test:5349?transport=tcp"],"username":"retroone-client","credential":"replace-with-your-client-credential"}]'
```

STUN 用于发现网络地址；TURN 在不能直连时转发浏览器之间的数据，会消耗 TURN 服务器的出口带宽。配置 TURN 不会提高设备的模拟性能，也不保证所有网络都能建立连接。示例域名仅用于说明，RetroOne 不会替你部署这些服务或自动开放防火墙端口。

配置仅接受 `stun:`、`stuns:`、`turn:`、`turns:` 地址，最多 8 项，每项最多 8 个地址。TURN 需填写 `username` 与 `credential`；两者最长均为 512 个字符。配置格式错误时，P2P 接口拒绝该配置，不会静默连接其他服务；浏览器入口仍可通过不依赖此配置的 HTTP 下载。

这些 ICE 参数会发送给参与下载的浏览器，因此应填写供客户端使用的 TURN 凭据，**不要填 TURN 服务的管理密码或生成凭据的主密钥**。使用临时凭据时，应在过期前更新部署配置并重新创建相应玩家容器。无需修改浏览器的 mDNS、安全策略或其他默认参数。

公开镜像不携带私有浏览器核心、ROM 或 BIOS。安装应用依赖不等于已经安装 EmulatorJS 的所有运行组件；缺少运行组件时，对应实验选项应保持不可用。运行组件准备流程见 [镜像构建说明](releasing.md)。

部署验证可以使用自行生成或可合法使用的测试内容：先确认单个浏览器能通过 HTTP 完成下载，再同时打开两个测试浏览器，确认分片校验成功且确实出现来自其他浏览器的字节。分别测试取消下载、关闭页面、连接失败和错误文件；之后再在自己的游戏上验证启动、输入与存档。

文档描述的是功能与部署要求，不表示某台 NAS 已完成升级，或所有文件格式、游戏、设备和网络均已通过验收。性能结论应记录具体游戏、客户端型号、浏览器版本、内核版本和测量结果。

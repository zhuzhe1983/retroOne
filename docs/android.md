# Android 本机游戏库

RetroOne Android 0.2.2 已提供可构建的原生客户端，支持连接服务、按平台浏览与搜索、全库排序、玩家收藏与最近游玩、分页查看封面和详情、后台下载、暂停与续传、离线查看本机文件，以及调用已安装的 PPSSPP。APK、构建和设备测试命令见 [Android 工程说明](../android/README.md)。

## 0.2.2 下载后游玩

- 完成下载与分片校验后，游戏卡片、详情和下载浮层自动显示 **▶ 游玩**，无须刷新游戏库。当前直启范围是 PSP ISO/CSO；缺少 PPSSPP、文件丢失或格式未适配时显示对应状态，不把“已下载”当作“可运行”。
- 右上角下载气泡显示当前任务百分比和任务数；完成后显示勾选提示。点击展开简短任务列表，可暂停、续传和游玩，或进入完整下载管理。浏览游戏库、收藏、Apps 等页面时持续显示，下载完成不会自动打开游戏。
- 气泡属于 RetroOne 应用界面，不申请系统悬浮窗权限；进入外部模拟器后由 Android 前台服务通知显示下载状态。
- 复用已经验证的 PPSSPP 文件授权启动方式，不更改模拟器配置与存档。离线时可从 **⋯ → 下载管理** 启动已完成文件。

适配按“平台、模拟器和文件格式”划分，并不是每款游戏都重写启动代码。后续候选是 [RetroArch Android 外部启动接口](https://docs.libretro.com/guides/cli-intro/)（指定 ROM 与 libretro 核心）和 [Eden Android](https://eden-emu.dev/)（Switch）；**本版未接入这两项**。接入还需验证文件权限、核心与 BIOS/固件、手柄及存档目录；RK3588 上的 Switch 性能须逐款实测。

0.2.2 构建、lint、23 项 JVM 测试通过。在独立、无界面的 Android 36.1 测试设备上，完成下载/游玩界面、后台下载生命周期、平台关注/排序/收藏共 3 项仪器测试；“游玩”实际拉起 PPSSPP 并核对原创测试程序的画面像素。测试只使用自建内容。RK3588 正在运行用户游戏，本轮没有覆盖安装；上述结果不能代替新版在该掌机上的安装验收。

## 0.2.1 掌机游戏库

- 宽屏采用两行导航：第一行是游戏库、收藏、最近游玩和右上角玩家；第二行放常用平台、平台选择、排序和搜索。移除了常驻的大标题、服务地址及说明，封面保持完整比例。
- **平台 +** 可搜索全部平台，点星标关注或取消关注。首页优先显示当前玩家关注的平台，其余位置补充最近玩过的平台；没有记录时提供常见平台入口。图标复用网页端各主机的轮廓。
- 平台关注、排序及升降序使用与网页相同的玩家设置。每次修改前读取最新设置，保留未修改字段；读取失败时不写入默认值覆盖原偏好。
- 下载资格与模拟器支持分开判断：服务器允许下载的独立文件仍可下载，即使没有 WASM 核心或 Android 直接启动适配。PSP ISO/CSO 可交给 PPSSPP；其他文件可导出后手动导入模拟器。目录、多碟和缺失文件会说明具体原因，不把它们当作完整 ROM 下载。
- 下载管理在顶部向下箭头；应用和连接设置收进 **⋯** 菜单。切换页面时丢弃未开始的旧封面请求，详情封面优先加载。

## 玩家数据与 Apps / Games

- 从 **⋯ → 应用** 打开 Apps；Apps 显示设备可启动应用的图标网格。可作为普通应用使用，也可在连接设置中打开系统默认桌面选择器，自行将 RetroOne 设为 HOME；安装不会自动切换桌面。
- 顶栏显示服务端当前玩家，点击切换。游戏列表、收藏、最近游玩和云存档请求始终使用该玩家的 `/p/<player>` 路径。
- 游戏详情可收藏或取消收藏，直接写入服务端，与网页共用。支持全部、我的收藏、最近游玩三个视图，原有游戏库完整分页，不限制为已下载或 PSP 游戏。
- 支持大众热度、名称、发行日期、加入时间、游玩次数、上次游玩、默认顺序七种排序，可切换升降序。排序由服务端在全库执行；排序偏好与网页按玩家共用，当前列表范围在本设备按玩家保存。
- 游戏详情的“云存档”读取当前玩家的兼容状态、快照版本、更新时间和大小。PSP 可下载最新游戏内存档并通过系统文件选择器导出 ZIP（含 `SAVEDATA/`）；读取期间沿用服务端短期占用协议，结束即释放。云端游戏正在运行或被其他客户端占用时拒绝读取，不结束游戏、不覆盖进度。
- 每份备份保存在按完整服务地址、玩家和游戏区分的应用目录；导出不写入 PPSSPP。当前**尚未实现自动双向同步、Android 模拟器玩家隔离或其他平台存档传输**，不得把“备份已下载”理解为“模拟器已接续进度”。Android 本机游玩记录也尚未回写服务端。

0.2.1 在 RK3588 / Android 13 上验证了完整库搜索与翻页、紧凑布局高度、PSP 下载入口和玩家选择；独立夹具验证了关注/取消关注平台、排序、收藏写回、实际文件下载及后台暂停续传。生产目录的检查为只读，测试写入只发生在独立夹具。尚未扩展其他 Android 模拟器的直接启动范围。

## 使用

1. 安装 APK，进入 **⋯ → 连接与模拟器设置**，填写 RetroOne 的服务地址。可用根地址，也可填写 `https://<主机>:8781/p/player1` 指定玩家；直连开发用 uvicorn 时使用其实际根地址。
2. 使用可信 HTTPS 证书，或在 Android 系统安装自己的 CA。没有“忽略证书”开关。可信局域网需要 HTTP 时，主动勾选明文连接；此时凭据与文件内容也没有传输加密。
3. 如果反向代理需要认证，可配置 HTTP Basic 或 Bearer Token。保留已有认证只保留**同一个完整服务地址**的凭据；切换任意新地址不会自动带上旧凭据。通过“读取并切换服务端玩家”选择同源玩家时，会复用当前认证。
4. 在 **游戏库** 中搜索、选择平台、翻页，打开详情查看服务端是否允许下载。界面会说明不支持的目录、多文件资源、禁用条目或缺失文件。
5. 点 **下载到掌机**，右上角展开进度浮层；收起后继续选游戏。可从气泡或 **⋯ → 下载管理** 查看准备、排队、下载、暂停、失败或已就绪状态。通知中可暂停全部。离开页面或回到桌面不停止正常前台服务下载；拒绝通知权限不会让下载变成静默系统任务，Android 的运行中应用入口仍可显示它。
6. 文件完整且分片校验通过后，在卡片、详情或浮层点 **▶ 游玩**，用 PPSSPP 启动支持的 PSP 镜像。其他独立文件可 **导出副本…**，通过系统文件界面选择新文件，再由自己配置的模拟器手动打开。导出时保持应用前台直到显示完成结果。

家庭玩家用于选择服务端游戏库视图，不是安全登录账户。Basic/Bearer 是反向代理认证，不是 MCP 令牌。网页登录、Cookie、OAuth 与客户端证书登录尚未接入。没有认证的服务只应按原项目的可信网络部署方式使用。

## 支持边界

| 内容 | 当前行为与证据 |
| --- | --- |
| PSP 单文件 ISO | PPSSPP 1.20.4 / Android 13 真机运行原创测试程序通过；不代表任意商业游戏、性能或存档已验证 |
| PSP 单文件 CSO | 原创压缩镜像执行路径已验证；小于 34 KiB 的极小 CSO 存在 PPSSPP 识别边界，客户端拒绝直启并提示导出 |
| PSP PBP | 可按服务端规则下载和导出；普通 FileProvider URI 在实测 PPSSPP 中出现目录解析失败，禁止直启 |
| PSP CHD、ZIP、7z | 可按服务端资格下载和导出，尚未验证可靠直启；不自动解压 |
| PPSSPP Gold / Legacy | 只检测明确包名和官方 Activity，显示未实机验证；本次设备只有免费版，不能宣称另外两版已验收 |
| 其他平台的独立文件 | 使用相同下载管理与导出，不提供未经验证的模拟器启动适配 |
| CUE/BIN、M3U、多碟、外部资源目录、DOS/Windows 目录 | 遵循服务端 `download-options` 的拒绝原因，不把单个入口冒充完整游戏 |
| BIOS、固件、密钥 | 不请求、不下载、不分发；需要时由用户自行合法提供给模拟器 |

模拟器可能在自己的“最近游戏”中保留已失效的 URI。请从 RetroOne 再次启动，或导出后通过模拟器的文件选择器打开。每次启动生成不同查询标识的 URI，避免 PPSSPP 复用旧授权失效时缓存的“文件不存在”结果。临时授权仅覆盖这个文件的读取，不授予整个目录或写入权限。

## 文件、存档与恢复

- 游戏只保存在应用私有的 `files/games/<随机任务ID>/` 中。服务端文件名必须通过严格校验；不会采用标题、绝对路径或 `Content-Disposition` 作为任意本机路径。
- SQLite 保存任务、来源、版本和状态。凭据单独用 Android Keystore AES-GCM 加密，任务数据库没有凭据。云备份和设备迁移排除应用数据，避免 ROM 或凭据被自动复制。
- 下载以 `.part` 暂存；续传前重新读取并校验完整分片，截去不完整或损坏的尾部。下载完成、fsync 后才改名并标记就绪。服务端版本变化时保留旧任务并停止，用户明确移除后才能重新下载。
- 进程中断、系统停止服务或重启设备后，不会自行下载；下次打开应用把未完成任务显示为暂停，点继续后复核本机分片。网络错误、磁盘不足和证书失败会明确报错，不承诺无限自动重试或跨重启后台下载。
- “移除本机副本”只删除该任务的文件；必须先暂停活动任务，且界面提醒先退出使用文件的模拟器。不会清理共享目录、服务器游戏或模拟器存档。
- 卸载或清除 RetroOne 数据会丢失私有下载。需要独立保留时先导出。SAF 创建目标文件不直接覆盖已有文件；导出失败或应用被结束时可能留下不完整目标副本，界面会提示处理。
- **模拟器自己管理存档。** 不读取、覆盖或同步 Android PPSSPP 的本机存档；服务端 PSP 存档可显式读取并导出备份。同一模拟器的不同 RetroOne 玩家共用其存档环境，没有实现玩家隔离。Android 本机启动不增加服务端云游戏游玩次数，也不创建服务器会话。

## 复用的服务协议

生产 API 未作改动。客户端复用以下接口：

- `GET /api/profiles`、`/api/platforms`、`/api/games?q=&platform=&favorite=&recent=&sort=&direction=&offset=&limit=60`、`/api/games/{id}`。
- `POST /api/games/{id}/favorite` 更新当前玩家收藏。
- `GET /api/settings/library`、`PUT /api/settings/library` 读取及更新当前玩家的平台关注与排序。
- `GET /api/games/{id}/cloud-save` 读取兼容性与状态，`POST .../lease` 获取最新快照，`POST .../release` 释放占用。Android 当前不调用云存档上传接口。
- `GET /api/games/{id}/download-options` 检查下载资格。
- `GET /api/games/{id}/download-manifest?transport=http`，遇到 HTTP 202 显示服务器分片准备进度并轮询。
- 清单中的同源 `download_url`，用精确 `Range` 请求读取。解析现有 `torrent_base64` 中的单文件 `info` 与 SHA-1 分片哈希，不连接 tracker、不使用 P2P、不调用 browser/launch 接口。

清单验证文件名、大小、版本、分片大小和数量，拒绝多文件 torrent 与越界编码。SHA-1 分片用于传输一致性检查，不代替 HTTPS 的来源验证。Range 必须返回精确的 206 / Content-Range；代理改写为 200、压缩 ROM、改变范围或跨域重定向时拒绝继续，避免错误续传或凭据泄露。

游戏分页固定每页 60 条，保持视图数量有界。封面只读取同源地址，设响应体和解码大小限制，并使用有界内存缓存；失败时显示平台占位，不伪造封面。未连接时只能查看已下载列表，未实现离线缓存完整远端目录。

主要代码：`ServerConfig` / `ApiClient` 管连接与来源边界，`Credentials` 管加密凭据，`DownloadManifest` / `Transfer` 管传输和校验，`DownloadStore` / `DownloadService` 管持久队列与前台服务，`Emulators` 管格式、包可见性与 URI，`MainActivity` 管原生界面。

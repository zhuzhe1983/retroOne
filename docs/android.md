# Android 本机游戏库

RetroOne Android 0.2.6 已提供可构建的原生客户端，支持连接服务、按平台浏览与搜索、全库排序、玩家收藏与最近游玩、分页查看封面和详情、后台下载、暂停与续传、离线查看本机文件，以及调用 PPSSPP、Eden 或经过设置与测试的 RetroArch ARM64。APK、构建和设备测试命令见 [Android 工程说明](../android/README.md)。

## 0.2.7 开发版：独立镜像入口（验收中）

新增 N64、NDS、PS1、Dreamcast 和 Saturn 的 RetroArch 入口。当前仍在真机验收；下表说明客户端接收哪些格式，不代表全部游戏已验证可玩。

| 平台 | 固定核心 | 自动准备的内容 |
| --- | --- | --- |
| N64 | `mupen64plus_next_gles3` | `.z64/.n64/.v64`，或唯一 ROM 的 ZIP；不转换字节序 |
| NDS | `melondsds` | `.nds` 或唯一 ROM 的 ZIP；DS/双模式卡带以 DS 模式启动 |
| PS1 | `pcsx_rearmed` | 独立、无父文件依赖的 CHD v5 CD 镜像 |
| Dreamcast | `flycast` | 独立 CHD v5 CD/GD 镜像；不包括 NAOMI ZIP |
| Saturn | `mednafen_saturn` | 独立 CHD v5 CD 镜像；性能与区域 BIOS 需实际核对 |

在已下载列表点 **检查本款游戏启动**。首次会显示所需核心与依赖，随后核对下载分片、格式并在已有授权目录建立摘要命名的副本。进入真实游戏并试过操作后，返回 RetroOne 确认 **画面与操作正常**，该游戏才显示“游玩”。打开模拟器、结构检查通过或看到片头均不会自动记录成功。切换后若 RetroArch 先退出旧实例，页面提供再次启动；不强行结束后台模拟器。准备过程可以取消，原下载与存档保持不变。

设置入口为 **⋯ → 连接与模拟器设置 → N64 / NDS / PS1 / Dreamcast / Saturn 设置**。Android 不允许本应用直接读取另一个应用的私有核心目录；BIOS 与核心仍由 RetroArch 管理，选择共享目录不等于依赖就绪。外部更新核心、BIOS 或配置后，请点 **核心或 BIOS 已更换，重新验证**。这些入口沿用 RetroArch 存档，暂未新增玩家隔离或云同步。

- N64 原文件上限 64 MiB、ZIP 128 MiB；DS 原文件上限 512 MiB、ZIP 576 MiB。只提取唯一匹配 ROM 及少量纯文本说明，保留原压缩包。旧卡带 ZIP 128 MiB、街机 ZIP 512 MiB 的范围不变。
- DS 检查 ARM 段与表的实际文件边界，允许裁剪卡带和原创程序；DSi 专用内容、外部 SD 与 Slot-2 不自动接入。双屏、触控和速度需要分别测试。
- CHD 暂限物理与逻辑长度各不超过 2 GiB；检查头部、map 与光盘元数据的范围，不自行解压全部数据块。CHD 容器不能证明平台或游戏兼容性。CUE/GDI/M3U、父 CHD、外部补丁及光盘 ZIP 仍需手动导入。
- PS1 建议使用对应区域真实 BIOS；不要求三份同时存在，核心的 HLE 回退仍有兼容性限制。Saturn 日本/亚洲 NTSC 使用 `sega_101.bin`，其他区域使用 `mpr-17933.bin`；特殊 ROM 卡按游戏配置。Flycast 的 VMU 与运行闪存属于保存数据，本应用不覆盖它们。

### GameCube · Dolphin（r2 开发版验收中）

已下载的 GameCube 单文件 **ISO / GCM / RVZ** 可从 **试运行 GameCube** 进入已安装的官方 Dolphin。首次先在 Dolphin 完成初始化，并保存、退出其他游戏；进入真实场景、试过画面与按键后，在 RetroOne 手动确认本款运行情况。安装成功、文件结构检查或片头画面都不会自动确认可玩。设置入口为 **⋯ → 连接与模拟器设置 → GameCube · Dolphin 设置**。Wii、WAD、WIA、WBFS、分卷、多盘和 ZIP 暂不开放。

直接读取已下载原件，无需额外复制镜像。容器检查不等于完整游戏验证：RVZ 仅检查有界外层头部、平台与范围，不解压全盘，也不能保证压缩内容中没有 NKit。显式 NKit 文件名及裸盘 NKit 标记不接入。

后台已有同款时，按钮为 **打开 Dolphin**。在 Dolphin 2609b 上，此操作可能打开游戏列表；请按系统返回或从最近任务回到原游戏，不会自动恢复。已在 Dolphin 正常退出后，选择 **已退出，重新启动** 才重新发送游戏文件。客户端不会注入返回按键或强制结束模拟器。

客户端在正常前后台切换中保留该文件的单独只读授权，直到你确认已退出；回到桌面、切换 RetroOne 玩家或暂时离开页面不会主动回收。可以在 GameCube 设置中选择 **已退出游戏，回收授权…**。正式会话中登记为仍授权给 Dolphin 的文件不能直接移除，需先保存退出并回收授权。Android 强制停止应用或重启设备也可能清除临时授权；已有会话记录仍可在确认退出后清理。Dolphin 存档暂不与云端同步，也不按 RetroOne 家庭玩家隔离；客户端不覆盖记忆卡、NAND 或原有配置。

r2 正式入口已在 RK3588 上验证《Animal Crossing》英文版：进入车站自由活动场景，左右移动并与 Porter 对话；HOME 后从客户端打开 Dolphin，按系统返回进入原会话，继续对话和移动。正常退出后同款冷重开已显示新实例的标题画面，再退出并从设置回收后，会话记录清除、兼容性确认保留。本次没有验证音频、实体手柄、存档重读或整款通关，也不代表 Wii 可玩。

拆分的撤权测试曾因新一轮 instrumentation 强制停止客户端，导致断言前 READ 已被系统清除；失败记录保留，不将它计为主动撤权成功。**同次测试内的权限回收与本轮最终数据保全仍待验收**。测试方式与限制见 [工程说明](../android/README.md#027-独立镜像与-dolphin-探针)。

## 0.2.6 经典卡带与街机兼容配置

在 **⋯ → 连接与模拟器设置 → 经典卡带** 中选择平台，安装对应核心，再运行该平台的原创测试程序。既有 NES 与共享目录设置可继续使用；新增平台各自确认画面与动作键，不能用 NES 的结果代替。Android 不允许其他应用直接读取 RetroArch 私有核心目录，因此界面区分应用未安装、共享目录待设置和平台待测试；不会只检测到 RetroArch 就宣称核心已就绪。

| 平台 | RetroArch ARM64 核心 | 独立卡带格式 | 原创探针的 RetroArch 按键 |
| --- | --- | --- | --- |
| SFC / SNES | snes9x | .sfc / .smc | B |
| GB / GBC | gambatte | .gb / .gbc（GBC 也可载入 .gb） | A |
| GBA | mgba | .gba | A |
| MD / Genesis | genesis_plus_gx | .md / .gen / .bin / .smd | Y（MD 原生 A） |
| SMS / GG | genesis_plus_gx | .sms / .gg | A（原生 II） |
| PCE | mednafen_pce_fast | .pce HuCard | A（原生 I） |

上述平台及 NES 也接受**仅含一份对应 ROM 的 ZIP**：下载分片校验后，有界检查 ZIP 结构和条目，流式核对实际大小与 CRC、卡带头，再提取到受控缓存并创建 SHA-256 命名的共享副本。原 ZIP 保留，内部文件名不会被用作写出路径。多游戏混装、嵌套压缩或多文件依赖不自动处理；SMD 交织内容保留原字节，交给 Genesis Plus GX 读取。普通卡带不需要额外 BIOS；可选启动 BIOS 沿用用户设置，PCE CD、SuperGrafx、FDS、Mega CD、32X 等不在这次范围内。

测试程序源码与图案为原创，构建时生成，不包含商业游戏。GB/GBC/GBA 的厂商 logo 区域留空，用于核心内置启动／跳过 BIOS 的诊断；若已自行启用外部启动 BIOS，请核对核心设置，RetroOne 不会自动修改。按住动作键后色条变化、松开恢复；GB 为灰度变化。更新核心后需重新测试所有使用该核心的平台，设置页提供入口。普通游戏仍可能因 mapper、特殊芯片或自身格式不兼容，需要逐款确认。

圆桌骑士的一个特定 MOD 新增 **MAME2003-Plus 兼容模式**：仅匹配已核验的完整归档 SHA-256，并核对全部 23 个成员；在独立副本中转换 13 个内部文件名，ROM 字节不变，原 ZIP 不动。按钮和启动提示明确标注 MOD 与所用核心。它不是 FBNeo 原版 DAT 匹配，也不会放行其他未知改版；需要额外安装 `mame2003_plus_libretro_android.so`，首次仍需确认真实画面、投币和输入。

新增平台与兼容模式的存档仍由 RetroArch 管理，尚无云同步或 RetroOne 玩家隔离；PSP、Eden 的现有流程保持不变。原创探针与实际游戏的验证范围见下表，不能据此推断整个平台全部兼容。

0.2.6 也支持内容完整的 FBNeo 克隆集及 NeoGeo：按逐成员 CRC 和大小判断，已有完整父集内容时不再因 `romof` 标签拒绝。根目录精确对应唯一基础集、且子目录仅含已知同族成员的合并包，可直接启动基础集；界面会提示 **合并归档：启动基础集**，其余版本保留在原 ZIP 中，暂不提供包内版本切换。缺父集、未知成员和多个候选仍需核对。

NeoGeo 缺少 BIOS 时显示 **配置 NeoGeo BIOS**；可从提示或 **街机设置 → 导入 NeoGeo BIOS** 选择自己的 `neogeo.zip`。客户端依据固定核心源码校验 4 个必需文件，另外 34 个 BIOS 选项不要求全部具备；所有实际提供的成员仍须通过校验。导入的受控副本与游戏放在独立启动目录，不改 RetroArch 的全局配置或 `system` 目录。若用户自己在核心中选用了其他 BIOS，仍需提供对应文件并验证；项目不附带或下载 BIOS。导入失败或取消会保留原选择，BIOS 更换后需重新确认游戏画面与输入。

## 0.2.5 Switch 与街机启动

已下载的 Switch NSP / XCI 显示 **用 Eden 启动**。首次使用需先在 Eden 中配置自己的固件与密钥；RetroOne 只授予 Eden 对这一个文件的只读权，直接读取下载原件，不复制大型镜像。启动接口可用不代表每款游戏都流畅：RK3588 上部分大型 3D 游戏存在低帧率或图形异常，需逐款确认。

回到桌面后点同款游戏，选择 **继续会话** 恢复后台游戏；如果 Eden 自己显示暂停界面，再点中央的 **继续模拟**。RetroOne 不代点模拟器界面或修改其暂停设置。如果已在 Eden 退出，则选 **已退出，重新启动**。Eden 0.2.1 收到带游戏地址的 Intent 会触发 ROM 切换，因此恢复会话不再发送地址；冷启动使用独立 Android 任务，避免重新打开游戏库时清理模拟器页面。切换其他游戏前先保存并在 Eden 退出，确认后回收上一份文件授权。启动异常会回收本次新授权；单纯离开前台不会撤权。设置页的 **Switch · Eden 设置 → 已退出游戏…** 可手动回收。Switch 存档仍由 Eden 管理，尚无云同步或家庭玩家隔离。

FBNeo 的独立 ZIP 显示 **检查街机启动**。安装 RetroArch ARM64 / FinalBurn Neo 核心，授权共享目录后，客户端校验下载分片、逐成员 CRC 和大小，再匹配固定版本的官方 DAT；唯一匹配的独立完整集会以确定的 ROM 集名称创建原样 ZIP 副本，不解包、不根据中文标题猜名称、不改动下载原件。首次运行返回后，需确认真实画面、投币／开始和动作键正常，才显示 **游玩**。

未匹配的归档显示 **ROM 版本待核对**，可查看原因或重新核对。MOD、其他 ROM 集版本、缺文件及可选 PLD 差异都可能导致严格匹配失败，**这不等于下载损坏**。自动校验在打开 ZIP 前检查结束记录与中央目录，限制物理大小 512 MiB、全部条目（含目录）4096 个、中央目录 4 MiB、展开量 2 GiB；ZIP64、多卷和自解压格式暂需手动导入，这些是街机直启边界，不改变通用下载能力。0.2.5 最初只开放无父集／BIOS 关联的完整集；0.2.6 的完整克隆、NeoGeo 和合并基础集处理见上文，其他 BIOS 家族及多个匹配结果仍需手动导入。客户端不会自动补齐、替换 ROM 或开启绕过 CRC 的 patched 模式。街机存档仍由 RetroArch 管理，尚未接入云同步与玩家隔离；更新核心后请在街机设置中重新验证。

本轮 39 项 JVM 测试、双 APK 构建及 lint 通过。RK3588 / Android 13 上，正式入口已验证：

- **Eden 0.2.1**：FFVII 冷启动并显示片头；Home 后恢复原会话，模拟器中央“继续模拟”按钮响应触屏，片头继续播放，未重新加载 ROM；正常退出后重开同款、切换到另一款游戏，以及退出后的单文件授权回收。本轮未验证 FFVII 游戏内菜单或完整游玩，模拟器自身暂停时仍需点中央“继续模拟”。
- **RetroArch 1.22.2 / FBNeo**：HSF2 的 ZIP 校验、共享副本、正式入口启动、投币、选人、实际战斗与触屏输入。圆桌骑士的未匹配改版被保留并提示核对版本，没有替换 ROM 或绕过校验。

## 0.2.3 已下载、本地内容与存档冲突

- **已下载** 位于“最近玩过”右侧，只展示已校验且仍存在的游戏文件。支持本机平台、搜索、下载时间／最近本机游玩／名称／大小排序；离线也能浏览与启动已适配的游戏。切换玩家不会隐藏同一设备的游戏文件。本机游玩时间暂不回写服务端。
- **⋯ → 本地内容** 分为“游戏文件”和“存档”，显示占用空间，可导出、移除游戏或独立备份。移除游戏文件需要确认，保留所有存档；移除一份备份也需要确认，不删除云端和模拟器进度。旧版备份缺少所属玩家信息时明确显示“待确认”。
- **游戏详情 → 云存档 → 同步 PPSSPP 存档…**：先在 PPSSPP 中结束游戏并退出，首次授权它正在使用的 `PSP/SAVEDATA` 目录。云端没有存档时，根据读取到的 PSP 游戏名称与编号选择本机存档；以后记住该服务、玩家和游戏的对应关系。云端已有内容时要求游戏编号一致，地区不同或混有多个游戏的快照会拒绝直接替换。
- 两边内容不同，显示各自时间、文件数、大小和云端版本，选择 **使用本机进度 → 云端** 或 **使用云端进度 → 本机**，也可取消。不会仅凭时钟新旧决定覆盖；选择期间任一端变化会要求重新比较。替换前的双方内容作为独立 ZIP 备份保留在本地内容中。
- 云端沿用现有占用与版本检查，写入期间续期；本机先暂存并校验新文件，再替换这一款游戏的目录。普通写入失败会回滚；中断后无法确认完整性时停止后续写入，保留备份供恢复。其他 PSP 游戏、即时存档、固件和密钥不参与同步。

这是 **PSP 游戏内存档的手动双向同步**。尚未在游戏运行期间自动同步，也未自动切换 PPSSPP 的玩家存档环境。切换家庭玩家后，先确认本机进度归属，再使用该玩家的云存档；不要把另一位家人的共享模拟器进度上传给当前玩家。Android 无法可靠判断第三方模拟器是否已经停止写盘，因此必须先退出 PPSSPP，不能只切回 RetroOne。

0.2.3 构建、lint、28 项 JVM 测试及 26 项服务器云存档回归通过。独立无界面 Android 36.1 设备验证了旧下载迁移、离线筛选、游戏／备份分别移除、收藏与排序、下载浮层及实际 PPSSPP 原创程序画面。存档验收使用真实服务 API 和独立 DocumentsProvider，覆盖取消、双向选择、双方并发变更拒绝、写入故障回滚及无关游戏保留；测试不使用生产存档。真机结果单独记录，不以这些测试代替所有 Android 存储提供方或商业游戏兼容性验证。

## 使用

1. 安装 APK，进入 **⋯ → 连接与模拟器设置**，填写 RetroOne 的服务地址。可用根地址，也可填写 `https://<主机>:8781/p/player1` 指定玩家；直连开发用 uvicorn 时使用其实际根地址。
2. 使用可信 HTTPS 证书，或在 Android 系统安装自己的 CA。没有“忽略证书”开关。可信局域网需要 HTTP 时，主动勾选明文连接；此时凭据与文件内容也没有传输加密。
3. 如果反向代理需要认证，可配置 HTTP Basic 或 Bearer Token。保留已有认证只保留**同一个完整服务地址**的凭据；切换任意新地址不会自动带上旧凭据。通过“读取并切换服务端玩家”选择同源玩家时，会复用当前认证。
4. 在 **游戏库** 中搜索、选择平台、翻页，打开详情查看服务端是否允许下载。界面会说明不支持的目录、多文件资源、禁用条目或缺失文件。
5. 点 **下载到掌机**，右上角展开进度浮层；收起后继续选游戏。可从气泡或 **⋯ → 下载管理** 查看准备、排队、下载、暂停、失败或已就绪状态。通知中可暂停全部。离开页面或回到桌面不停止正常前台服务下载；拒绝通知权限不会让下载变成静默系统任务，Android 的运行中应用入口仍可显示它。
6. 文件完整且分片校验通过后，在卡片、详情或浮层启动：PSP 使用 PPSSPP，Switch 使用 **用 Eden 启动**；NES 与其他经典卡带先完成对应 RetroArch 平台设置与测试，街机按提示核对 ROM 集、BIOS 与实际输入。尚未适配的独立文件可 **导出副本…**，通过系统文件界面选择新文件，再由自己配置的模拟器手动打开。导出时保持应用前台直到显示完成结果。

家庭玩家用于选择服务端游戏库视图，不是安全登录账户。Basic/Bearer 是反向代理认证，不是 MCP 令牌。网页登录、Cookie、OAuth 与客户端证书登录尚未接入。没有认证的服务只应按原项目的可信网络部署方式使用。

| 其他平台的独立文件 | 使用相同下载管理与导出，不提供未经验证的模拟器启动适配 |
| CUE/BIN、M3U、多碟、外部资源目录、DOS/Windows 目录 | 遵循服务端 `download-options` 的拒绝原因，不把单个入口冒充完整游戏 |
| BIOS、固件、密钥 | 不附带、不下载、不分发；NeoGeo 可由用户选择自己的 BIOS ZIP，其他内容由用户提供给模拟器 |

模拟器可能在自己的“最近游戏”中保留已失效的 URI。请从 RetroOne 再次启动，或导出后通过模拟器的文件选择器打开。每次启动生成不同查询标识的 URI，避免 PPSSPP 复用旧授权失效时缓存的“文件不存在”结果。临时授权仅覆盖这个文件的读取，不授予整个目录或写入权限。

## 文件、存档与恢复

- 下载原件保存在应用私有的 `files/games/<随机任务ID>/` 中。服务端文件名必须通过严格校验；不会采用标题、绝对路径或 `Content-Disposition` 作为任意本机路径。
- SQLite 保存任务、来源、版本和状态。凭据单独用 Android Keystore AES-GCM 加密，任务数据库没有凭据。云备份和设备迁移排除应用数据，避免 ROM 或凭据被自动复制。
- 下载以 `.part` 暂存；续传前重新读取并校验完整分片，截去不完整或损坏的尾部。下载完成、fsync 后才改名并标记就绪。服务端版本变化时保留旧任务并停止，用户明确移除后才能重新下载。
- 进程中断、系统停止服务或重启设备后，不会自行下载；下次打开应用把未完成任务显示为暂停，点继续后复核本机分片。网络错误、磁盘不足和证书失败会明确报错，不承诺无限自动重试或跨重启后台下载。
- “移除本机副本”只删除该任务的文件；必须先暂停活动任务，且界面提醒先退出使用文件的模拟器。不会清理共享目录、服务器游戏或模拟器存档。
- 卸载或清除 RetroOne 数据会丢失私有下载。需要独立保留时先导出。SAF 创建目标文件不直接覆盖已有文件；导出失败或应用被结束时可能留下不完整目标副本，界面会提示处理。
- **模拟器自己管理存档。** 仅在用户授权目录、退出模拟器并明确选择版本后，进行 PSP 游戏内存档同步；双方原内容可导出备份。同一模拟器的不同 RetroOne 玩家共用其存档环境，没有实现玩家隔离。Android 本机启动不增加服务端云游戏游玩次数，也不创建服务器会话。

## 复用的服务协议

生产 API 未作改动。客户端复用以下接口：

- `GET /api/profiles`、`/api/platforms`、`/api/games?q=&platform=&favorite=&recent=&sort=&direction=&offset=&limit=60`、`/api/games/{id}`。
- `POST /api/games/{id}/favorite` 更新当前玩家收藏。
- `GET /api/settings/library`、`PUT /api/settings/library` 读取及更新当前玩家的平台关注与排序。
- `GET /api/games/{id}/cloud-save` 读取兼容性与状态，`POST .../lease` 获取最新快照，`POST .../release` 释放占用。`POST .../heartbeat` 在写入期间续期，`PUT .../cloud-save` 带占用令牌与基础版本上传明确选中的本机进度。
- `GET /api/games/{id}/download-options` 检查下载资格。
- `GET /api/games/{id}/download-manifest?transport=http`，遇到 HTTP 202 显示服务器分片准备进度并轮询。
- 清单中的同源 `download_url`，用精确 `Range` 请求读取。解析现有 `torrent_base64` 中的单文件 `info` 与 SHA-1 分片哈希，不连接 tracker、不使用 P2P、不调用 browser/launch 接口。

清单验证文件名、大小、版本、分片大小和数量，拒绝多文件 torrent 与越界编码。SHA-1 分片用于传输一致性检查，不代替 HTTPS 的来源验证。Range 必须返回精确的 206 / Content-Range；代理改写为 200、压缩 ROM、改变范围或跨域重定向时拒绝继续，避免错误续传或凭据泄露。

游戏分页固定每页 60 条，保持视图数量有界。封面只读取同源地址，设响应体和解码大小限制，并使用有界内存缓存；失败时显示平台占位，不伪造封面。未连接时只能查看已下载列表，未实现离线缓存完整远端目录。

主要代码：`RetroArch` / `RetroArchPolicy` / `RetroArchFlow` 管 NES 依赖、共享副本和测试设置，`ServerConfig` / `ApiClient` 管连接与来源边界，`Credentials` 管加密凭据，`DownloadManifest` / `Transfer` 管传输和校验，`DownloadStore` / `DownloadService` 管持久队列与前台服务，`Emulators` 管格式、包可见性与 URI，`LocalGames` / `LocalContentView` 管设备游戏与备份，`SaveSyncFlow` / `PspSaveDirectory` 管 PSP 手动同步与授权目录，`MainActivity` 管原生界面。

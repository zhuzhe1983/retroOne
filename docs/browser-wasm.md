# 浏览器 WASM 实验功能

RetroOne 可以让符合条件的较大 ROM 在浏览器本地模拟。详情页提供 HTTP 和 WebTorrent 两种下载方式；游戏计算和画面渲染由当前设备承担。

默认行为保持不变：**只有符合原有条件、文件及解压后大小均不超过 20 MiB 的游戏，才自动使用浏览器模式**。本页介绍的实验选项必须手动选择，不会改写游戏的默认启动配置，也不会把游戏库中的大镜像自动下载到手机。

这项功能复用已有的 EmulatorJS WASM 核心。不同平台、游戏和客户端的兼容性差别很大；选项可用表示已通过文件、内核等启动条件检查，不表示这款游戏已经通过实际游玩或 60 FPS 验证。

## 选择启动方式

打开一款游戏的详情页，在开始按钮下选择 **启动方式**：

| 选项 | 下载与运行方式 | 适合的情况 |
| --- | --- | --- |
| 自动选择（推荐） | 保持原来的 20 MiB 自动规则 | 日常使用，无需考虑内核或文件大小 |
| 云游戏 | ROM 留在服务器，浏览器接收画面和声音 | 手机、性能不足的设备、需要家人或智能体观战 |
| 本机 WASM · HTTP 下载（实验） | 从 RetroOne 下载完整 ROM，然后在本机运行 | 想直接验证本机性能，或浏览器之间无法建立连接 |
| 本机 WASM · WebTorrent（实验） | NAS 的 HTTP Web Seed 提供下载；其他参与浏览器可以通过 WebRTC 互传分片 | 同一游戏有多个家庭设备同时下载或共享 |

下拉框中不可用的选项会标为“不可用”；展开 **查看不可用选项的原因** 可以查看缺少的条件。当前设备不满足线程、图形或网络要求时，也会限制对应选项。键盘可使用标准下拉框操作；手柄聚焦后按确认键，会循环选择可用方式。

选择本机模式后，界面会说明需要下载的 ROM 体积。下载完成后，仍需等待模拟器加载。**当前实现不是边下边玩，也不是云端画面串流。** P2P 改变的是文件来源，不会减少 ROM 的实际体积或模拟器的内存需求。

## 当前支持范围

较大 ROM 的实验范围先限制在 GBA、Nintendo 64、Nintendo DS、PlayStation 和 PSP。现有小型卡带平台也可以尝试显式选择下载方式，但仍须通过各自的格式和体积检查。

| 平台 | 实验入口接受的主要格式 | 额外条件 |
| --- | --- | --- |
| GBA | `.gba`，或只包含一个卡带文件的可验证 ZIP | 已安装对应浏览器核心 |
| Nintendo 64 | `.z64`、`.n64`、`.v64`，或合格的单卡带 ZIP | 已安装对应浏览器核心；性能因游戏而异 |
| Nintendo DS | `.nds`，或合格的单卡带 ZIP | 已安装核心及 `bios7.bin`、`bios9.bin`、`firmware.bin`；双屏和触控需求仍取决于游戏 |
| PlayStation | 独立 `.pbp` | 已安装核心并提供所需 BIOS；本版不开放 CUE/BIN 多文件组合、M3U 或 CHD |
| PSP | 独立 `.iso`、`.cso`、`.pbp` | PPSSPP 线程核心、配套资源、HTTPS、跨源隔离、共享内存及 WebGL 2 |

格式限制按照 RetroOne 当前锁定的 EmulatorJS 4.2.3 核心确定，不能套用原生模拟器的格式列表。例如，原生 PPSSPP 可以支持的某种格式，并不代表当前 WASM 构建也能加载。本版不把 7z、多文件光盘、依赖父包的街机集合或完整 PC 游戏目录打包后直接交给浏览器。

Switch、PS2、PS3、GameCube、Wii 和当前未接入浏览器核心的平台继续使用云游戏。上游新增平台不等于 RetroOne 已安装、适配或验证它。

PSP 是实验性较强的路径。上游明确要求启用线程，并不保证具体游戏的兼容和图形表现。RetroOne 同时检查锁定核心所需的 WebGL 2 和配套资源。详见 [EmulatorJS PSP 文档](https://emulatorjs.org/docs/systems/psp/)；浏览器线程依赖的跨源隔离要求见 [Emscripten pthreads 文档](https://emscripten.org/docs/porting/pthreads.html)。

## 内存和存档

实验模式默认限额为 **512 MiB**，管理员最多可提高至 **1 GiB**。文件体积和可验证的解压后体积都不能超过限额。限额只是服务器允许提供的内容大小，不表示所有客户端都能分配足够内存。

当前锁定的 EmulatorJS 会完整加载 ROM，并写入模拟器的内存文件系统；加上模拟器内存、临时缓冲区和图形资源，浏览器的实际内存占用可能达到 ROM 体积的数倍。更换 HTTP 或 WebTorrent 不会改变这一点。实现依据见 [EmulatorJS 4.2.3 加载代码](https://github.com/EmulatorJS/EmulatorJS/blob/v4.2.3/data/src/emulator.js)。

建议先用较小的自有游戏，在内存充足的电脑上验证输入、声音、保存和恢复，再尝试更大的文件。手机浏览器更容易受到内存限制；页面被系统回收或浏览器崩溃时，请使用云游戏，不要只提高服务器下载限额。

本地模拟继续使用当前玩家的浏览器存档空间和既有存档工具；**浏览器存档与云端模拟器存档分开**，切换运行方式不会自动转换进度。HTTP 和 WebTorrent 是同一浏览器模拟器的两种下载路径，不会创建第二个家庭玩家。

需要家人或智能体观看时，请使用云游戏。当前的观战、服务端截图及远程控制链路不捕获本地浏览器的 WASM 游戏画面。WebTorrent 下载连接也不等于游戏联机：它不会同步人物、房间、存档或手柄输入。

## WebTorrent 的工作方式

本版采用 **HTTP Web Seed 保底、浏览器间 WebRTC 互传** 的结构：

```text
NAS 上的 ROM ── HTTP Web Seed ──→ 浏览器 A ──→ 本机 WASM 模拟器
                                      ↕ WebRTC 分片
                                  浏览器 B
```

NAS 提供完整文件和分片校验所需的元信息。参与同一游戏下载的浏览器，可以从 HTTP 节点及已拥有相应分片的浏览器接收内容。**没有其他浏览器做种时，仍可从 NAS 的 HTTP 节点下载，这不是 P2P 故障。** 下载页应区分 HTTP 来源和其他浏览器来源的数据，不能把全部下载流量都称为 P2P 加速。

这不要求 NAS 通过 aiortc 扮演 WebRTC 文件发送端，也不把普通 BitTorrent TCP/UDP 客户端当成浏览器节点。浏览器节点之间使用 WebRTC；HTTP Web Seed 是另一条标准下载路径。WebTorrent 支持 Web Seed，并会在下载期间把已有分片提供给其他节点，详见 [WebTorrent API 文档](https://webtorrent.io/docs)。

默认使用自行部署的私有 Tracker，并限制在应用提供的游戏内容范围内，不连接公共 Tracker。浏览器页面的参与是下载和分享分片，不会把整个 NAS 目录公开做种。

Tracker 复用 WebTorrent 项目的 [bittorrent-tracker](https://github.com/webtorrent/bittorrent-tracker)。所有玩家共用网关的 `/rom-tracker` WebSocket 路由，通过现有 HTTPS 端口访问；不需要再对外开放 Tracker 的内部端口。每次启动获得仅适用于当前内容的限时票据。共享数据目录中的 `.webtorrent-secret` 是部署私钥，不应上传、公开或复制到客户端。

## 已完成的验收

2026-10-25 使用自制的 32 MiB GBA 测试程序验证了 HTTP 下载和 WASM 运行。另在 NAS 的独立 Docker 测试实例和 Linux Chrome 147 的两个独立浏览器上下文中验证：A 从 NAS 完成下载并启动模拟器；B 被禁止访问 HTTP ROM 地址后，仍全部通过 A 获得 32 MiB，并启动模拟器。停止 B 的分享后，模拟器继续运行。

这证明了下载、分片校验、浏览器互传与 WASM 的完整路径，不代表全部商业游戏、手机或跨公网网络均已通过测试。Mac 测试环境中仅有 mDNS 候选的连接未成功，HTTP Web Seed 正常；网络限制时应保留 HTTP 下载，或由管理员配置下面的 STUN/TURN 服务。

本版不提供公共 Tracker 配置。可选的 STUN/TURN 是浏览器建立网络连接所需的服务，与查找游戏下载节点的 Tracker 不是同一个功能。

浏览器间连接还受 NAT、防火墙、网络隔离和 WebRTC 策略影响。Docker Bridge 中的 HTTP 节点能够访问，不代表两个浏览器之间一定能互连。部署时应分别验证 HTTP 下载和浏览器互传；不能仅凭网页打开或 Tracker 建连成功就声称 P2P 可用。

如果 WebTorrent 下载无法完成，可以返回游戏详情，**主动改选 HTTP 下载**。界面不会未经选择切换成云游戏或启动另一个游戏会话。

## 管理员配置与验证

`RETROONE_WASM_MAX_BYTES` 控制实验模式的体积上限，单位为字节。例如默认 512 MiB 对应 `536870912`；硬上限为 `1073741824`。此变量不改变自动模式的 20 MiB 阈值，也不会增加客户端可用内存。部署时须将变量传入每个玩家容器，并检查后续新增玩家实例是否继承一致的设置。

`RETROONE_WEBRTC_ICE_SERVERS` 是可选的 JSON 数组，默认 `[]`：**不预设公共 STUN/TURN，也不连接公共 Tracker**。默认状态下浏览器只尝试当前网络可用的直接连接；跨路由、VPN 或公网 NAT 环境可能无法互连，HTTP Web Seed 仍是下载保底来源。私有 Tracker 能交换信令，不代表已经打通浏览器间的数据通道。

管理员可以配置自己运营或明确选用的 STUN/TURN 服务。例如，在部署使用的 `.env` 中设置以下示例，并将主机名、用户名和凭据替换为实际服务配置：

```dotenv
RETROONE_WEBRTC_ICE_SERVERS='[{"urls":"stun:stun.example.test:3478"},{"urls":["turn:turn.example.test:3478?transport=udp","turns:turn.example.test:5349?transport=tcp"],"username":"retroone-client","credential":"replace-with-your-client-credential"}]'
```

STUN 用于发现网络地址；TURN 在不能直连时转发浏览器之间的数据，会消耗 TURN 服务器的出口带宽。配置 TURN 不会提高设备的模拟性能，也不保证所有网络都能建立连接。示例域名仅用于说明，RetroOne 不会替你部署这些服务或自动开放防火墙端口。

配置仅接受 `stun:`、`stuns:`、`turn:`、`turns:` 地址，最多 8 项，每项最多 8 个地址。TURN 需填写 `username` 与 `credential`；两者最长均为 512 个字符。配置格式错误时，WebTorrent 入口明确报错，不会静默连接其他服务；普通 HTTP 下载不依赖这项配置。

这些 ICE 参数会发送给参与下载的浏览器，因此应填写供客户端使用的 TURN 凭据，**不要填 TURN 服务的管理密码或生成凭据的主密钥**。使用临时凭据时，应在过期前更新部署配置并重新创建相应玩家容器。无需修改浏览器的 mDNS、安全策略或其他默认参数。

公开镜像不携带私有浏览器核心、ROM 或 BIOS。安装应用依赖不等于已经安装 EmulatorJS 的所有运行组件；缺少运行组件时，对应实验选项应保持不可用。运行组件准备流程见 [镜像构建说明](releasing.md)。

部署验证可以使用自行生成或可合法使用的测试内容：先确认单个浏览器能通过 HTTP 完成下载，再同时打开两个测试浏览器，确认分片校验成功且确实出现来自其他浏览器的字节。分别测试取消下载、关闭页面、连接失败和错误文件；之后再在自己的游戏上验证启动、输入与存档。

文档描述的是功能与部署要求，不表示某台 NAS 已完成升级，或所有文件格式、游戏、设备和网络均已通过验收。性能结论应记录具体游戏、客户端型号、浏览器版本、内核版本和测量结果。
